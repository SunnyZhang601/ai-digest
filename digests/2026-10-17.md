**Box CEO Aaron Levie**

Aaron Levie argued that the biggest misread among those predicting the end of software engineering was assuming the world only needs a fixed amount of software, so automating the field would reduce labor demand. The opposite is happening: because agents can use tools, work with computers, write software on the fly, and process data like humans but far faster, software can now be thrown at problems that never could reasonably be digitized. That makes engineering more important to the economy, not less, since banks doing new forms of trading, life sciences research, and manufacturing supply chains are all increasingly shaped like software problems. His conclusion: we won't be coding manually, but almost everything will be code, which puts people who understand it in a fantastic position.

Aaron Levie 认为，那些预言软件工程终结的人最大的误判在于：他们假设世界只需要固定数量的软件，所以把这个领域自动化就会减少劳动力需求。但事实恰恰相反：因为 agent 会使用工具、能操作电脑、能即时写软件、还能像人一样（但快得多）处理数据，现在可以把"软件"用在那些以前根本无法合理数字化的问题上。这让工程在经济中的重要性上升而非下降，因为银行做新型交易、生命科学的研发、制造业的供应链自动化，都越来越像软件问题。他的结论是：未来我们不会手动写代码，但几乎所有东西都会是代码，所以懂代码的人处在极佳的位置。

**The MAD Podcast with Matt Turck: What Happens When Billions of AI Agents Hit Your Database? (Andy Pavlo)**

The Takeaway: The real bottleneck for agentic AI isn't smarter models, it's the unglamorous discipline of guardrails, permissions, and sandboxed database branches, and most teams are relearning lessons databases solved decades ago.

Andy Pavlo, a Carnegie Mellon professor whose database courses trained a generation of engineers (and, as it turns out, the models themselves), recently founded ClickHouse Labs. His core argument is that agents behave a lot like humans at the API level, just running around the clock, so the controls you'd apply to a human developer are the controls you need for an agent. The difference is volume, and he expects a 10x to 100x increase in queries hitting databases as every person ends up with hundreds of agents acting on their behalf. "Think of them as like toddlers," he says of agents. "Little more sophisticated than that, but like, you don't then run wild or do whatever they want on a database." The alternative to guardrails, sitting and clicking approve on every action, simply doesn't scale.

On the memory debate between file systems and databases, he's blunt: "What is a file system? It's a database, right? Everything's a database." What matters is that the context handed to an agent is human-readable text, and a real database system gives you safety guarantees, shared state across multiple agents, and transactionality for free. He's equally skeptical of native graph databases for the context layer, noting SQL added property graph support in 2023 and that Postgres should be the default first choice for most agent workloads. On text-to-SQL, he cites a large bank that went from roughly 60% accuracy off the shelf to about 95% only after years and millions spent building a proper semantic layer, a warning that downloading a tool won't get you there.

The most striking data point: over 60% of open source database systems now have commits coming from agents, tracked nightly by his database-of-databases project. He thinks agents can vibe-code an entire database system with enough tokens and guidance, though the old adage still holds that the first 90% takes three years and the last 10% takes seven. His advice to students is unchanged in spirit: understand what a database is actually doing, because everyone will interact with one, even if nobody is hand-tuning knobs anymore.

The Takeaway：agentic AI 真正的瓶颈不是更聪明的模型，而是那些不起眼的功夫：guardrail、权限控制，以及沙箱化的数据库分支；而大多数团队正在重新学习数据库几十年前就已经解决的问题。

Andy Pavlo 是卡内基梅隆大学的教授，他的数据库课程培养了一代工程师（事实证明，也训练了模型本身），他最近创立了 ClickHouse Labs。他的核心论点是：在 API 层面，agent 的行为和人类很像，只是 7×24 小时不间断运行，所以你对人类开发者施加的控制，就是对 agent 需要的控制。区别在于量级，他预计随着每个人都拥有数百个替自己行动的 agent，打到数据库上的查询量会增长 10 倍到 100 倍。"把它们当成幼儿来看，"他这样形容 agent，"比那稍微复杂一点，但你不能让它们在数据库上撒野、想干什么就干什么。"guardrail 的替代方案是坐在那里对每个动作点"批准"，而这根本无法规模化。

在文件系统与数据库之争的 agent 记忆问题上，他说得很直接："什么是文件系统？它就是一个数据库，对吧？一切都是数据库。"关键在于喂给 agent 的 context 是人类可读的文本，而真正的数据库系统免费提供安全保证、多 agent 共享状态和事务性。他对用原生图数据库做 context layer 同样持怀疑态度，指出 SQL 在 2023 年就加入了 property graph 支持，而 Postgres 应该是大多数 agent 工作负载的默认首选。关于 text-to-SQL，他举例说某家大银行从开箱即用的约 60% 准确率，花了好几年、几百万美元构建合适的语义层之后才做到约 95%，这是一个警告：随便下载一个工具到不了那个水平。

最惊人的数据点是：现在超过 60% 的开源数据库系统有来自 agent 的 commit，这是他的 database-of-databases 项目每晚追踪的结果。他认为只要有足够的 token 和引导，agent 可以 vibe-code 出整个数据库系统，不过老话依然成立：前 90% 要三年，最后 10% 要七年。他对学生的建议在精神上没变：要理解数据库到底在做什么，因为每个人都会和数据库打交道，即使已经没有人再手动调参数了。
